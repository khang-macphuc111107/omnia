### 1.1 `App Codex Desktop Siêu Nhẹ.md` — Complete Requirements & Architecture

#### 1.1.1 Overview & Evaluated Lightweight Desktop Coding-Agent Applications
The document `App Codex Desktop Siêu Nhẹ.md` defines the architectural foundation for an ultra-lightweight, high-performance desktop coding agent environment. It establishes that developer friction in modern AI-assisted engineering arises predominantly from the "Electron Tax" (unbounded V8 memory growth, garbage collection pauses, sluggish startup, and high IPC latency). The specification evaluates six desktop coding-agent patterns:

1. **T3 Code**: Focuses on clean daily driver ergonomics, multi-provider model switching, and lightweight local orchestration.
2. **Orca**: Extends coding-agent capabilities with browser automation, headless DOM manipulation, and scriptable multi-stage tasks.
3. **Zed (Agent Panel)**: Written in pure Rust and rendered on the GPU via GPUI. Leverages the **Agent Client Protocol (ACP)** to plug in external agents (Codex, Claude Agent, OpenCode, Cursor) with isolated per-thread worktrees and direct file editing without switching windows.
4. **Claude Desktop (Code Tab)**: First-party Anthropic client with deep Computer Use integration, local filesystem sandbox, and preview capabilities.
5. **ChatGPT Desktop (Codex)**: First-party OpenAI client with integrated macOS/Windows OS automation and workspace indexing.
6. **Pivot / OMP**: Bridges the lightweight UI shell of T3 Code with the multi-agent supervisory brain of Oh My Pi (OMP), decoupling UI rendering from the agent execution core.

#### 1.1.2 Technical Architecture & Non-Functional Performance Budgets
To achieve an order-of-magnitude reduction in resource consumption while maximizing agent execution power, the following non-functional constraints and architectural invariants are mandated:

- **GUI Framework & Windowing**: Native Rust backend paired with Tauri v2 or native Win32 desktop shell (`omnia-native.exe`). Win32 Mica backdrop, Direct2D/DirectWrite rendering, and DWM Dark Mode integration.
- **Accessibility & Automation**: Server-side COM `WM_GETOBJECT` UI Automation (UIA) provider exposing explicit control types: single-line `ControlType.Edit` (`IValueProvider`, Control 114) and multiline `ControlType.Document` (`TextPattern`, Control 112). `WH_CBT` modal dialog hooks for Windows `#32770` dialogs.
- **Memory Footprint Ceiling**:
  - Idle state: $< 30\text{ MiB}$ physical RAM (verified: `omnia.exe` starts at $\approx 5.74\text{ MiB}$ RSS).
  - Active execution state: $< 100\text{ MiB}$ physical RAM under high concurrency.
- **Latency & Startup Budgets**:
  - CLI warm startup: $\le 15\text{ ms}$ (verified: median $11.57\text{ ms}$).
  - Desktop shell cold launch: $\le 300\text{ ms}$.
  - Post-first-byte SSE wire-idle watchdog: $\le 55\text{ s}$ timeout on `/v1/responses`.
  - Max-effort `/v1/messages` Attempt-0 keepalive headroom: $180\text{ s}$.

The benchmark report establishes that the empirical performance of an AI coding agent is determined by the multiplicative product of two distinct layers:

#### 1.4.1 `Collatz Conjecture Mathematical Analysis.pdf` (31 Pages, 149 Citations)
The document provides an exhaustive state-of-the-art survey of the $3x+1$ problem, formalizing requirements for automated mathematical verification in AI harnesses:
